# CDT-switcher

CDT-switcher 是运行在独立 Linux 控制机上的阿里云国际站 ECS 轮换服务。程序根据账户的本月 CDT 非中国内地流量和累计运行时长选择节点，启动并验证目标服务后，将原节点置于节省停机状态。

项目适用于多个账户各管理一台 ECS 的场景。Telegram 提供状态查询、节点切换和保护停机命令；可选启用账户账单查询与每日费用汇总。

## 功能

- **节点调度**：根据流量、运行时长和账户可用性选择目标，支持自动及手动切换。
- **服务检查**：通过实例状态、公网 IP 和 TCP 端口检查确认目标可用，再停止原节点。
- **额度保护**：节点超出配置阈值后切换；无可用节点时执行全局保护停机。
- **状态持久化**：保存切换进度、运行时长、流量快照和事件记录。
- **Telegram 管理**：发送调度通知，提供运行报告、流量查询和控制命令。
- **账户账单**：查询本月税前费用和产品明细，在每日运行报告中附加账户费用。
- **可选 OOS 恢复**：使用当班标签选择需要定时启动的实例。

## 部署条件

- 一台持续在线的 Linux 控制机，独立于被管理的实例。
- 已创建的 ECS、稳定公网地址和随系统启动的业务服务；实例需支持 `StopCharging` 节省停机。
- 各账户的 CDT 服务已开通，相关公网流量已纳入 CDT 计量。
- 每个账户各自的 RAM 用户凭据，以及具有查询、启停和标签管理权限的自定义策略。
- Telegram Bot Token 和授权聊天 ID。

稳态目标是保留一个运行节点；切换期间可短暂同时运行多个节点。实际服务连续性受库存、抢占回收、网络和业务服务状态影响。项目管理已有实例，不负责购买实例、创建替代实例、分配 EIP 或更新客户端路由。

## 部署流程

1. 完成[控制台准备与最小权限配置](docs/permissions.md)。
2. 按[部署指南](docs/deploy.md)使用 Git、uv 和 systemd 安装服务。
3. 填写 [config.example.yaml](config.example.yaml) 中的账户、Telegram 和阈值配置。
4. 完成只读验证，启动服务后通过 `/check` 检查运行状态。
5. 按需配置[账单查询](docs/billing.md)或 [OOS 定时恢复](docs/oos-setup.md)。

Python 最低版本为 3.10，部署指南使用 Python 3.12。配置和运行数据保存在控制机本地。

## Telegram 命令

| 命令 | 功能 |
| --- | --- |
| `/check` | 查看系统状态、切换进度及各节点的运行时长和流量快照。 |
| `/traffic` | 刷新并查看各账户本月 CDT 流量。 |
| `/switch` | 根据调度规则选择并切换节点。 |
| `/switch A` | 切换至账号键 `A` 对应的节点。 |
| `/breaker confirm` | 停止全部受管实例并确认节省停机。 |
| `/resume` | 从全局保护停机中恢复，仍需满足节点资格条件。 |
| `/last` | 查看最近 10 条事件。 |
| `/bill` | 查看全部账户本月税前费用，需启用账单功能。 |
| `/bill A` | 按产品展开账户 `A` 的费用，需启用账单功能。 |

账号键来自 `accounts` 映射；`instance_name` 用作显示名称。`telegram.chat_ids` 授权整个聊天，在授权群组内具有发送命令权限的成员均可触发控制操作。报告和通知发送到全部授权聊天。

## 可选账单功能

为各账户配置的 RAM 用户增加 `bss:DescribeBillList` 权限，并在 `config.yaml` 顶层设置：

```yaml
billing:
  enabled: true
```

重启后启用 `/bill` 和每日 23:58（UTC+8）的费用汇总。手动查询在五分钟内复用账户结果，缓存仅保存当月内存汇总；失败显示当前金额未知，同月旧结果附带查询时间。账单统计范围为凭据所属账户，费用不参与实例调度。授权、金额口径和终端查询见[账单指南](docs/billing.md)。

## 运行边界

- 同一批实例由一个控制器管理。本机文件锁不能协调不同主机上的控制器。
- 流量查询和账单数据存在延迟，阈值需要按账户实际额度和业务流量留出余量。
- 运行时长用于调度均衡，根据巡检观测累计，不等于云平台的计费时长。
- 节省停机不代表账户全部资源停止计费；磁盘、EIP 等资源费用需单独核对。
- TCP 探测验证端口连通性，业务认证及端到端可用性由业务客户端验证。

状态、切换步骤、持久化和故障处理见[运行机制](docs/state-machine.md)。
