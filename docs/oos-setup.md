# OOS 看门狗控制台配置步骤（每账号各配一套，免费）

> 作用：脚本死亡时，OOS 每小时把带 `duty=on` 标签的实例拉起，守住"最后一台已知好机"。
> 标签契约：脚本写标签（在线 on / 其余 off），OOS 只读标签执行拉起。OOS 不能跨账号，**每个账号都要配一套**。

## 前提

- 实例已打标签（脚本运行后 T5 会自动写；首次也可手动在 ECS 控制台给实例加 `duty=off`）
- 当前登录的是被管账号本人（或其 RAM 管理员）

## 步骤（每个账号重复一次）

1. **开通 OOS**：控制台搜索"运维编排 OOS"→ 开通（免费）。
2. **创建定时执行**：
   - OOS 控制台 →「自动化任务」→「定时运维」→ 创建
   - 模板选择：**`ACS-ECS-BulkyStartInstances`**（批量启动，原生支持按标签筛选目标；
     `ACS-ECS-ScheduleToStartInstances` 亦可，但 Bulky 版更贴合标签契约）
3. **定时设置**：
   - 模式：周期性（cron），**每小时**执行一次，如 `0 0 * * * ?`（按控制台向导选"每小时"即可）
   - 时区与脚本宿主机一致（Asia/Shanghai）
4. **目标实例选择方式**：**按标签筛选**
   - 标签键 `duty`，标签值 `on`
   - 地域选实例所在地域（如中国香港 cn-hongkong）
   - 速率控制：并发速率随意（目标恒为 1 台）；**最大错误次数选 0%**——
     拉起 Running 实例幂等成功不算错误；真失败（NoStock/欠费/权限）时
     0% 让本次执行标红可见，100% 会把失败静默吞掉。单次执行失败不影响
     定时规则，下个整点照常重试。
5. **权限角色**：按向导授予 OOS 服务角色 `AliyunECSFullAccess` 或更窄的自定义策略
   （`ecs:StartInstance` 可限定单实例 ARN；`ecs:DescribeInstances` 需按标签检索，
   资源范围须 region 级或 `*`，不能锁单实例）。
6. 保存并启用。可在「执行历史」里确认每小时触发成功。

## 验证

- 手动把当班实例停机（普通停机即可），等下一个整点执行窗口，OOS 应将其拉起。
- 脚本恢复运行后，首个 tick 的 reconcile 会重新对齐标签与全局态，幂等无冲突。

## 注意

- **标签默认 off**：只有脚本明确确认在线的实例才会是 `duty=on`；切勿手动把备用实例标成 on（否则 OOS 会每小时把它拉起，白烧计算费和流量）。
- 全局熔断（BREAKER）期间全网 `duty=off`，OOS 不拉起任何实例——这是正确行为（流量已耗尽）。
- 脚本宿主机恢复后无需人工干预 OOS；两者职责正交。
