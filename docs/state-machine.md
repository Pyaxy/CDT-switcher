# 运行机制

本文说明 CDT-switcher 的调度条件、切换过程和故障处理。安装与授权分别见[部署指南](deploy.md)和[权限配置](permissions.md)。

## 1. 控制模型

`accounts` 中的每个配置项包含一组账户凭据和一台 ECS。控制器周期性读取云端状态，将其与本地切换进度及保护意图结合，决定下一步操作。

正常稳态的目标是保留一个运行节点，其余节点处于节省停机状态。切换过程中允许原节点和目标节点同时运行；全局保护状态下目标为全部停机。库存不足、实例回收和网络故障可能导致暂时无可用节点。

实例由管理员预先创建。程序不创建替代实例，也不修改 DNS、EIP 绑定或业务客户端配置。

## 2. 实例观测

实例信息通过 `DescribeInstances` 按配置中的实例 ID 查询。

| 状态 | 判定 | 处理含义 |
| --- | --- | --- |
| `RUNNING` | `Status=Running` | 参与运行时长累计，继续检查地址及服务。 |
| `STARTING` | `Status=Starting` | 等待启动完成。 |
| `STOPPING` | `Status=Stopping` | 等待停止完成。 |
| `STOPPED_SC` | `Status=Stopped` 且 `StoppedMode=StopCharging` | 已确认节省停机。 |
| `STOPPED_KM` | `Status=Stopped`，未确认 `StopCharging` | 按需要重新提交节省停机请求。 |
| `NOT_FOUND` | 查询成功且实例列表明确为空 | 按实例不存在处理。 |
| `UNKNOWN` | 查询失败、响应结构无效或状态无法识别 | 暂停依赖该观测的云端写操作并告警。 |

公网地址必须与配置的 `eip` 匹配。`OperationLocks` 中的 `Recycling` 标志作为回收预警输入；TCP 连接用于检查业务入口是否可达。

任一受管实例处于 `UNKNOWN` 时，两个控制循环暂停云端写入。手动保护停机请求仍可先保存为本地意图，待观测恢复后继续执行。

实例查询按节点累计连续失败次数，达到 `observation_failure_threshold`（默认 3）后才发送 TG 告警；成功取得一次明确状态即清零，进程重启也会清零。计数包含常规巡检、快速控制循环及切换中的实例复核，按实际查询次数计算，同一快照重复检查不累计。每个节点的重复告警仍受 `alert_repeat_interval_sec` 限制。阈值只延后通知，首次失败即暂停自动启停；CDT 查询、TCP 探测和启停操作的错误不使用此计数。

## 3. 流量与运行时长

### 流量

程序调用 `ListCdtInternetTraffic`，按 `BusinessRegionId` 汇总账户本月非中国内地流量。地域 ID 以 `cn-` 开头且不是 `cn-hongkong` 的条目归入内地，其余条目计入本程序的流量值。

原始字节数除以 `1024 ** 3`，配置和界面将该数值标记为 GB。查询范围是账户，不限于配置中的单台 ECS；核对控制台时需匹配账户、月份、地域范围和单位。

默认每 20 分钟刷新，进程启动时也会刷新。只有本月且未超过 `traffic_stale_sec` 的快照参与候选选择；查询失败不会覆盖上一份有效数据。接口数据存在延迟，保护阈值应低于账户实际可用额度，并根据业务流量预留余量。

月初不会将流量快照强制置零，也不通过比较新旧数值确认云端已重置。每次查询都保存接口实际返回值，例如新月返回 0.3 GB 就记录 0.3 GB。快照的月份依据本地采集时间判断，不能证明云端数据已完成月度切换；若月初接口仍返回较高的旧值，程序会按该值继续判断资格。

### 运行时长

常规巡检每观测到一台实例为 `RUNNING`，为其账号增加一次 `patrol_interval_sec`。这是用于调度均衡的本地计数，不是云端精确计费时长。控制器停机、巡检延迟、未知观测及重启会影响累计结果。

新加入的账号以已有计数的平均值作为起点。时长按 UTC+8 自然月保存，月初任务重置本月计数。

新增 C 时，在 `accounts` 下添加完整配置并重启服务即可；保留原数据库、状态文件及 A/B 账号键。所有账号共用数据库表，启动巡检自动新增 C 的当月记录，流量刷新自动写入 C 的快照，无需手动建表。C 的运行时长起点是数据库中已有当月计数的平均值，并非从零开始；这不影响 C 的实际 CDT 流量。C 也参与全局未知态保护，应先确保实例 ID、权限和业务端口配置正确。

月初任务在每月 1 日 00:05（UTC+8）投递重置意图，由控制循环执行；它直接将本月运行时长置零，不等待流量数值下降。由于月份分区在 00:00 已切换，00:05 的清零也会覆盖新月最初几分钟已累计的本地时长。

## 4. 候选选择与触发条件

候选节点需同时满足：

- 本月累计运行时长低于 `tmax_hours`。
- 具有有效 CDT 快照，流量低于 `traffic_threshold_gb`。
- 未被当前进程标记为欠费账号。
- 启用 `billing.threshold_usd` 时，该账号本月最高已知账单保护金额未达到阈值。金额未知只告警，不将其视为零，也不单独排除候选；流量和时长规则继续生效。

资格筛选完成后，通过 `scheduling.strategy` 选择候选：

| 策略 | 选择顺序 |
| --- | --- |
| `balanced`（默认） | 当月累计运行时长从低到高；相同则按 `accounts` 配置顺序。 |
| `priority` | 账号的 `priority` 从小到大；同级按当月累计运行时长从低到高；再相同则按配置顺序。 |

每个账号的 `priority` 为非负整数，省略时为 100。`balanced` 不使用优先级；旧配置不添加新字段时行为不变。策略仅对原规则已经筛选出的候选择优，不放宽额度、流量有效期或欠费条件，也不改变启动失败后的重试和回滚规则。实例是否仍存在、能否启动及服务是否可达，在观测和切换阶段继续验证。

例如 A/B 为主力、C 为备用时，设置 `scheduling.strategy: priority`，并在 A/B 的账号配置中设置 `priority: 10`，C 设置 `priority: 100`。只要本次候选名单中仍有 A 或 B，就不会自动选 C；A/B 同级继续按运行时长均衡。若希望严格 A、B、C 优先，可分别设置为 10、20、100。

策略用于自动选机、未指定账号的 `/switch`、恢复运行、多机在线纠偏以及切换中目标超限后的重选；每个入口保留原候选范围。显式 `/switch C` 仍可选择符合资格的 C，不受其他节点优先级限制。策略不触发主动回切：C 正常当班时，即使 A/B 在跨月后恢复资格，C 仍继续运行，直到原有条件触发切换或收到手动命令。修改配置后需重启服务。

| 触发条件 | 行为 |
| --- | --- |
| 当班节点流量或时长达到阈值 | 尝试切换至符合条件的节点；无候选时执行保护停机。 |
| 当班账号账单保护金额达到阈值（可选） | 同样进入正常切换流程，无候选时保护停机；超额账号本月不能重新选入。 |
| 回收预警或运行节点丢失 | 根据观测和候选状态尝试恢复服务。 |
| `/switch` 或 `/switch 账号键` | 进入同一切换流程；指定节点仍需满足资格条件。 |
| 服务连续探测失败 | 默认告警；开启 `auto_switch_on_service_down` 后尝试切换。 |
| `/breaker confirm` | 保存全局保护意图并执行全实例停机。 |
| `/resume` | 从保护状态恢复，重新检查候选条件。 |

全局保护期间，人工或 OOS 启动的实例仍会被控制器按保护意图停止。每月 1 日 00:05 的恢复任务会刷新用量并检查候选；存在可用节点时可解除保护并恢复运行，包括此前由手动命令进入的保护状态。

## 5. 切换步骤

切换游标保存在 `state.json` 中。每个步骤基于当前观测推进；异步 API 调用返回成功后仍需回读状态。

| 步骤 | 动作 | 完成条件与失败处理 |
| --- | --- | --- |
| T1 资格检查 | 核对目标流量、时长及账户状态。 | 不满足时终止本次目标切换。 |
| T2 启动目标 | 调用 `StartInstance` 并等待。 | 回读 `RUNNING` 后进入探测；库存不足按配置退避，超时终止本次尝试。 |
| T3 服务检查 | 核对公网地址并探测 TCP 端口。 | 默认连续 3 次成功；超时启动回滚处理。 |
| T4 停止原节点 | 停机前再次核对目标状态、地址和 TCP 连接，然后提交 `StopCharging`。 | 停机对象确认 `STOPPED_SC` 或已不存在后完成；目标不可用则回到服务检查，停机失败持续重试。 |
| T5 收尾 | 核对实例状态、更新当班标签并回读。 | 目标可用、其余实例停机及标签符合预期后，保存结果并发送完成通知。 |

全局保护直接进入停止全部实例及收尾流程。回滚时停止未通过验证的目标，并根据原节点状态决定继续使用原节点或进入无在线节点状态。

标签写入失败时保留收尾进度并重试。手动全局保护请求及切换中已确认的目标超限，由控制循环优先处理，可替换正在进行的切换流程。

云端查询、TCP 探测和启停请求是独立操作，无法组成跨系统原子事务。目标可能在检查后发生回收或故障；后续观测用于发现偏差并继续处理。

## 6. 全局状态

| 状态 | 含义 |
| --- | --- |
| `STEADY` | 根据运行数量确定的单节点稳态；持续进行服务、额度和备用节点检查。 |
| `TRANSITION` | 正在执行 T1–T5 切换。 |
| `BREAKER` | 全局保护停机状态，持续检查并处理意外启动。 |
| `DEGRADED_MULTI` | 切换之外观测到多个运行实例，选择符合条件的保留节点并停止其余节点。 |
| `DEGRADED_ZERO` | 非保护状态下没有运行节点，按候选状态尝试恢复。 |
| `UNKNOWN` | 尚未完成初始分类或缺少有效状态信息。 |

`STEADY` 是控制状态，不等价于业务服务可用性保证。TCP 故障默认只触发告警，需结合报告中的观测信息判断。

## 7. 并发与持久化

常规巡检和快速控制循环共用一个非阻塞控制锁，同一进程内串行执行实例控制。Telegram 控制命令和定时事件通过意图进入控制流程；账单使用独立的后台查询及缓存锁。

| 数据 | 内容 | 保存方式 |
| --- | --- | --- |
| `state.json` | 全局状态、当班账号、切换游标、保护意图和观测摘要。 | 临时文件写入、同步后替换目标文件。 |
| SQLite `runtime_counters` | 账号按月累计的运行时长。 | SQLite 事务。 |
| SQLite `traffic_snapshots` | 流量值及查询时间。 | SQLite 事务。 |
| SQLite `events` | 调度与异常事件。 | SQLite 事务。 |
| 账单缓存 | 当前月的格式化汇总、查询时间和失败状态。 | 仅内存，重启清空。 |
| SQLite `bill_budget`（启用阈值后写入） | 账号按月的最新保护金额、最高已知金额、查询时间和失败状态。 | SQLite 事务；金额使用十进制文本保存，未知值不写成零。 |

数据库与状态文件分别持久化，不构成统一事务。恢复流程结合本地记录和新云端观测继续处理。

状态文件读取失败时，运行中的进程可使用最近一次有效的内存状态；冷启动且没有可读取状态时，从空状态开始分类。丢失的保护意图或切换历史无法仅依靠当前实例状态完整还原，因此迁移和备份需同时保留配置、数据库及状态文件。

启动前对配置、数据库和状态文件路径获取本机排他锁。进程退出后锁由内核释放，锁文件保留。该机制不提供跨主机互斥。

## 8. 调度与配置

| 任务 | 默认时间或间隔 | 配置字段 |
| --- | --- | --- |
| 常规巡检及运行时长累计 | 60 秒 | `patrol_interval_sec` |
| 快速控制循环 | 5 秒，最少 1 秒 | `probe_interval_sec` |
| CDT 查询 | 20 分钟 | `traffic_interval_min` |
| 账单保护查询（可选） | 启动后后台刷新，之后默认 60 分钟 | `billing.refresh_interval_min`；仅启用阈值后注册。 |
| 每日运行报告 | 23:58，UTC+8 | 固定调度。 |
| 月初重置与恢复 | 每月 1 日 00:05，UTC+8 | 固定调度。 |
| 历史清理 | 每日 00:30，UTC+8 | 保留周期见配置示例。 |

切换超时、库存退避、停机重试、告警节流和数据保留参数见 [config.example.yaml](../config.example.yaml)。其中库存退避通过 `nostock_backoff_sec` 列表配置，默认 `[60, 120, 240, 480]` 秒；仅模板注明的字段支持环境变量覆盖。

## 9. 通知与可选功能

通知包含调度开始、完成、保护停机、回收预警、额度事件和异常信息。显示名称优先采用 `instance_name`，账号键保留用于命令；`/last` 展示最近 10 条事件。网络发送由队列处理，网络故障会延迟报告；队列容量有限，进程退出时未发送消息不持久化。

账单查询启用后，费用加入每日报告。默认只报告；显式配置 `billing.threshold_usd` 后，正常巡检和快速控制循环读取本地预算快照，将已知超额作为额外的候选排除及切换条件，`/check` 显示保护金额和阈值。后台查询不占用控制锁，不直接调用云端启停接口。查询失败、数据过期、空账单或币种不符时告警，仍依靠原有流量和时长规则；已有同月超额证据不因失败、过期或金额回落而解除。新月份不使用旧月证据；月初无有效金额时仍明确显示未知。账单延迟和其他资源持续计费意味着此功能不能承诺费用不超过阈值，详见[账单指南](billing.md)。

OOS 通过 `duty=on` 选择当班实例。控制器为当班节点设置该标签，为其他节点删除 `duty` 标签；OOS 独立执行，标签变更存在时间窗口。配置及运行边界见 [OOS 指南](oos-setup.md)。
